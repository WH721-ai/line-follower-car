# 判据与实测数据

每一条都标注了**判据、机理、实测数字、修法**。数字来自一台具体的车
（轮径 30.09 mm、轮距 144 mm、7 路灰度间距 6.7 mm、视场 ±40 mm、前视 66 mm、200 Hz 环），
**结论可以移植，数值必须重算**。

---

## §1 摆 = 阻尼不足，不是刚度太大

### 判据

| 现象 | 结论 |
|---|---|
| 降增益后 **幅度变小但周期变长** | 刚度问题，继续降有救 |
| 降增益后 **几乎没变化** | **阻尼不足** ⇒ 唯一正解是「还相位给 D」 |

### 我们的弯路

连犯 5 次：`ė` 低通从 120 → 180 → 260 ms。结果 `ωn ≈ 6 rad/s` 处 D 的净超前
只剩 **+23°** ⇒ 阻尼只兑现 `sin 23° = 0.39` ⇒ 标称 ζ 0.88 实际 **0.34**。

### 压噪用限幅，不用低通

```
噪声来源：量化台阶 6.7 mm / 采样周期 5 ms = 1.34 m/s 的假速度
真实信号：横向速度物理上 ≤ 0.36·v（0.70 m/s 时 0.25 m/s）
⇒ 噪声比信号大 4~9 倍 ⇒ 限幅可以干净削掉，且零相位代价
```

★ **限幅值必须按速度缩放。** 固定限幅 `X` 隐含钳位角 `sinθ = X/v`：

```
X = 0.25： v=0.70 ⇒ 20.9°（e≈25 mm）
           v=0.86 ⇒ 16.9°（e≈20 mm）   ← 摆幅刚过 ±20 mm 就把 D 钳死
```

P 项还在随偏差增长，D 已被钳住 ⇒ 等效相位滞后 ⇒ 阻尼塌陷 ⇒ 正反馈发散。

### 抬 `wheelMax` / 放开限幅后必然出现振荡

**隐形限幅一直在替你压增益。**

实测：`wheelMax = 60 rad/s` 时，直道可执行舵量上限只有 **0.87 rad/s**，
而 10 mm 偏差就需要 **1.02** ⇒ 位置环被钳成"恒速回正"⇒ **反而不摆**。

抬到 68 之后这层限幅消失 ⇒ **增益第一次全额兑现** ⇒ 摆。

> **把"放开一个限幅"当成"把增益调大 30%"来处理。**

## §2 弧内摆 = 位置环静差（几何必然）

### 核心公式

```
turn_req = (v/R) / 执行增益
e_req    = turn_req / Kp
```

实测（视场半宽 **40 mm**）：

| 弧 | R | v | `turn_req` | `e_req` | 占视场 |
|---|---|---|---|---|---|
| 500 mm | 0.500 | 0.50 | 1.11 | 20.6 mm | 52% |
| 685 mm | 0.685 | 0.60 | 0.97 | 18.0 mm | 45% |
| 342 mm | 0.342 | 0.42 | 1.36 | 25.2 mm | 63% |
| **292 mm** | 0.292 | 0.42 | 1.60 | **29.6 mm** | **74%** |
| 392 mm | 0.392 | 0.52 | 1.47 | 27.3 mm | 68% |

> **光"待在圆弧上"就吃掉 45~74% 的视场。**
> 剩给扰动的余量 < 10 mm，而量化台阶就是 6.7 mm ⇒ 一个台阶就出界。
>
> **这就是"直道幅度精确为 0、弧内幅度 30~36 mm"的全部原因。**
> 不是增益没调好，是几何必然。

### 两个方向都堵死

| 动作 | 好处 | 代价 |
|---|---|---|
| Kp ↑ | `e_req` ↓ | `ζ ∝ 1/√Kp` 恶化；且 `e=40mm` 时 `Kp·0.040` 超舵量限幅 ⇒ **bang-bang** |
| Kp ↓ | ζ 略好 | `e_req` ↑，更靠边界 |
| Kd ↑ | ζ ↑ | **有硬上限**（量化尖峰会打死环路，本车 Kd>12 就死） |

### 唯一解：前馈，而且可以直接算

```
arcff = sgn · 0.90 · (v / R)
```

实测验证：R500@0.50 的前馈稳态 = **0.90**，公式给 `0.90 × (0.50/0.500) = 0.90`，**一个数不差**。

**为什么钉 0.90 而不是钉满**：执行增益 0.9007 ⇒ 钉 0.90 意味着前馈只出 81%，
剩下的 19% **刻意留给位置环**（对应 `e ≈ 3~6 mm`）。钉满会让位置环空转、失去纠偏能力。

### 为什么"学习"这条路走不通

学习链 = 陀螺低通 0.25 s + 跟踪 0.20 s ≈ **0.45 s 滞后**：

1. **弯头 0.45 s 前馈是 0**，正好是瞬态最需要它的时候；
2. 学习链通常有门限（"只在 `|e| < 27 mm` 时学"），而缺前馈时 `e` 必然冲过 27 mm
   ⇒ **学习被冻结** ⇒ 前馈永远学不上来。
   **这条通道在最需要它的时候恰好失效。**

### 一次性投递 100% 不生效

试过"进弧那一帧 arm、下一帧消费"：836 条记录里，进弧标志、Kp 切换全都正常，
而 `arcff` 从 +0.00 **平滑走到** −0.07，**没有任何跳变**。

> 前馈这类状态量，一律**每帧幂等赋值**。

### 前馈一有值，boost 必须让位

boost（大偏差补舵）和前馈是**重复补偿**。

实测：`arcff` 学到 1.45，boost 又按 `(20.1−6.8)/1000×60 = 0.79` 加进来
⇒ 合计 **2.24 > 限幅 2.00** ⇒ 满舵过转 ⇒ 线往左滑 ⇒ `e` 稳在 20 mm 下不来（**正反馈**）。

★ 但**让位要线性淡出，不要硬切**：实测硬切会在跨阈值那一帧让舵量从 1.922 一帧掉到 1.122
（0.80 rad/s 的阶跃），这个阶跃本身就是后面那串摆荡的起爆点。

## §3 出弧那一瞬 = 全程需求舵量最大

实测：弧内舵量打满 −2.00 持续 0.32 s ⇒ 陀螺冲到 **−1.80**
（该段只需 −1.11，**过转 62%**）。

出弧瞬间直道标志置真 ⇒ 直道档把舵量权限砍半（2.00 → 1.00）
⇒ 需要刹车的 0.18 s 里要 +2.00 只给 +1.00 ⇒ `e` 从 +6.7 冲到 **+40 丢线**。

> **任何"出弧即切档"的动作，都必须保证舵量权限不降。**
> 等于别在刹车最难的时候松刹车。

## §4 某个里程冲出去

### 4.1 十字的灰度签名 = 直角

**十字路口和 90° 直角在灰度阵列上表现完全相同**（线在车底横过来 ⇒ 整条阵列压白）。

我们的赛道段二（6.7~22.9 m）**全是圆弧，没有任何真直角**，但路上有两个十字。
最要命的那个：过完之后**仅 490 mm** 就是 R292 的 90° 小弯
⇒ 在十字上误转 90° 后再也对不准入口。

**修法**：按里程段**整体禁用转角判据**——在那些段里直接清空转角状态，
让"横边 / 观察窗 / 直角"四条路径全部不可达。

### 4.2 降速窗口的空洞

相邻两窗之间如果有缝，那条缝会被判成"真直道"⇒ Kp 减益 + 舵量上限收紧
⇒ 那里若有真曲率，直接被推出视场。

**检查间隙 ≤ 250 mm**（约 2 个前视量）。

### 4.3 但"延长前一窗口"只在两窗之间是直线时才对

如果两段弧**相切**，把前一窗右端往前挪 = **在弧内降速** ⇒ 必坏：

前馈按当前速度算，速度一降 ⇒ 需求舵量 `v/R` 变小，但前馈还是按旧速度给
⇒ 持续**过转** ⇒ 往弧内切 ⇒ 丢线。

> **铁律：不要在弧内改速度。**
> 提前减速只能用"时间型前视"（`v × 0.35 s`），不要动窗口端点。

### 4.4 判据表与速度表必须分开

为了让车提前减速，把降速窗口起点提前了 470~918 mm，
而"是不是直道"的判定遍历的**正是同一张表**
⇒ **那些直线被当成了弯道** ⇒ Kp ×2.5、舵量上限翻倍、直道平滑全关。

实测：17.80 m 处 Kp 在 120 ms 内翻 2.5 倍 ⇒ 1.34 s 后摆幅从 ±6.7 发散到 **±40 丢线**。

> **速度窗口可以提前，弯道判定不能提前。**

### 4.5 判错代价不对称

- 漏判一个转角 ⇒ 少转一个弯，还能救
- 误判一个转角 ⇒ 直接出赛道，救不回来

⇒ 转角判据必须有一层**里程授权表**（只在已知转角 ±1300 mm 内允许），窗外一律撤销。
**宁可漏，不可误。**

## §5 一提速就摆

四条并行检查，缺一条就会得出错误结论。

### 5.1 环路增益算错

如果偏航率环是 `wCmd = a·turn − b·GyroZ`，而门控阈值极低（直道也走这条式子），
那么**直道真实环路增益是 `Kp × a`，不是 `Kp`**。本车 `a = 1.6`。

我们一开始按 1.0 算 ⇒ 低估 60% ⇒ 所有"为什么这个速度能跑、那个就摆"的分析全部偏掉。

```
ζ ∝ 1/√Kp_eff
ωn ∝ √Kp_eff
```

### 5.2 Kp 必须严格 ∝ v

```
ζ = (Kd/2)·√(a·v/Kp)
```

若 `Kp ∝ v` ⇒ `ζ` 与 `v` 无关（完美）。若只提 `v` 不提 `Kp` ⇒ `ζ ∝ 1/√v` ⇒ **必降阻尼**。

### 5.3 量化台阶：算"每台阶几拍"

```
每格耗时 = 探头间距 / v
v = 0.28, 间距 6.7 mm, 5 ms 环 ⇒ 24 ms ⇒ 4.8 拍
v = 0.70 ⇒ 1.91 拍
v = 0.86 ⇒ 1.56 拍   ← 边缘
v = 0.92 ⇒ 1.46 拍   ← 不可用
```

**< 1.6 拍时一帧可能跨一整格**，差商直接出 1.34 m/s 假速度。
**想更快，先加前视或提高灰度分辨率，不要硬提速度。**

### 5.4 电压墙

转向靠差速，外轮需要额外轮速 = **额外电压**。

实测 `uq ≈ 10.4·v`（0.84 m/s → 8.74 V），uq 限幅 10.0 V：

| v | uq | 剩余 | 可执行舵量 |
|---|---|---|---|
| 0.70 | 7.28 V | 2.72 V | 1.54 rad/s（54%） |
| 0.84 | 8.74 V | 1.26 V | 0.93 rad/s |
| **0.86** | ~8.94 V | ~1.06 V | **上限** |
| 0.90 | 9.36 V | 0.64 V | 被限住 |

> ★ **"跑了一段时间才开始摆"是电压特征**，不是热漂移：
> 满电勉强有 0.26 V 余量，掉到 11.5 V 以下就归零。

### 5.5 外轮饱和

```
外轮轮速 = v/Rw + ω·Lw/(2Rw)
```

本车 `wheelMax = 60 rad/s`（0.9027 m/s）。`v = 0.92` 时**直行基础轮速就 61.15**（贴顶）
⇒ 只剩内轮 ⇒ **单向转向** ⇒ 锯齿摆。**0.92 永远不要再试。**

## §6 降速不能治摆

被实车**否掉**的方案：弯道速度全部降 15%，结果 **"跑得更差了"**。

```
ζ ∝ √v      ⇒ 降速让阻尼比下降
ωn ∝ √v     ⇒ 周期变长、单次摆幅更大
```

省下来的那点 `e_req` 根本补不上阻尼损失。

> **不要再试图用降低速度换稳定。**
> 唯一例外：降速让某个舵量需求回到限幅**之内**（解饱和）——那是另一件事。

## §7 改了一个数完全没生效

### 7.1 钳位写在会被覆盖的位置

```c
wCmd = ...;                            // ①
wCmd = constrain(wCmd, -1.1, 1.1);     // ② ← 无效
if (lineDirect) { wCmd = ...; }        // ③ 重算，钳位被覆盖
```

**现象**：日志一直打印"上限 1.10"，车实际舵量明显超标，改这个数毫无效果。

**规则**：变量被赋值 ≥2 次 ⇒ 钳位写到**最后一次赋值之后**；
改完搜一遍 `变量名\s*=` 确认顺序。

### 7.2 事件式写法有致命盲区

```c
if (cur != slowIdx) { slowIdx = cur; lineRunV = table[cur].v; }
```

任何别的逻辑改完 `lineRunV` 之后，只要没跨窗口，**这里永远不会重新接管**。

实测：降速表给 0.56 → 提档逻辑改成 0.84 → `slowIdx` 还是 0 ⇒ **不再自愈**
⇒ 整段弧都用基准速度跑 ⇒ 必冲出。

**修法**：加一条每帧幂等热修复（一次比较的开销）。

### 7.3 三处都在写增益

1. 上位机命令
2. 起跑初始化
3. **分段增益表**（按里程查，每帧一阶跟随）——**它会覆盖前两处**

"我明明改了 Kp 为什么日志里还是旧值"的答案通常是第 3 处。

### 7.4 起跑清状态：`ePrev` 不能清 0

要清 `arcff` / `ė` / `steer` / `gyroF`，但**位置差商的上一帧值要用当前读数初始化**。
清 0 会让首帧差商算出 `(e − 0)/dt` = **~4 m/s 的假速度**，这一帧就足以把车打偏。

### 7.5 斜坡的位置和方向都有讲究

- **加速斜坡的起点必须在足够长的直线上**。一段只有 500 mm 的直线加完速正好扎进最小半径的弯
  ⇒ 速度环滞后 + 转向瞬态全撞在入弧点。
  不够就把加速点**往后挪到下一段长直线**，不要靠"把斜率调小"硬塞。
- **入弯那一帧不许斜坡下降**。前馈按速度算，速度没降下来之前给足前馈 = 主动过转。
  实测：0.40→0.28 的斜坡让进区头 0.15 s 给 1.53 而实际只需 0.79 ⇒ **过转 60%** ⇒ 一进区就跑出去。
  原版一帧阶跃反而是对的。
  > **斜坡只能用在曲率不变的两个稳态之间**（弧内匀速、弧尾到直道）。
- **由指令速度算控制量之前，速度指令必须先过斜坡**，否则指令阶跃 = 舵量阶跃。

## §8 一次完整的故障复盘

> 比结论更有用的是过程。

**现象**：R8 末端（约 8.8 m）冲出去，"上次跑还行"。

1. **先怀疑数据**：导出只有 538 行（应 1700+）⇒ **车在 8.10 m 就丢线了**，
   后面是搜线过程。用户描述的"8.8 m 出问题"本身就是错的。
2. **逐帧看舵量**：7.10 m 时 `e` 三帧 −6.7→−20.0，`turn` 打满 −2.000，陀螺冲到 −1.86
   （该段只需 −1.11）⇒ **过转 62%**。
3. **问"过转为什么能发生"**：弧内打满 0.32 s ⇒ 需求远超限幅
   ⇒ 因为前馈是 0（学习链没学到），全靠 PD 用 `e` 换。
4. **改前馈（直接算）**：第一次**没生效**——一次性投递 100% 失败 ⇒ 改每帧赋值。
5. **还有一处**：出弧瞬间直道标志置真 ⇒ 舵量权限砍半 ⇒ 把该段直道上限 1.00 → 1.80。
6. **仍然摆**：数据说直道幅度 **精确为 0**，摆全在弧内 ⇒ 算 `e_req`（74% 视场）
   ⇒ **不是增益问题，是几何问题**。
7. **好一点，但十字那里出去**：十字签名与直角相同 ⇒ 段二禁用转角判据。
8. **想提速**：提到 0.86，段二单独验证全过；**拼回全程四圆区末尾右转角过不去**
   ⇒ 降速救不回来（那是方向错，不是位移大）⇒ **回滚，用最慢最稳的一版参赛**。

**教训**：真正省时间的不是"快点调好"，而是**先花半天把数据链路做对**。
前面所有反复，都发生在"看不到逐帧数据"的那段时间里。
