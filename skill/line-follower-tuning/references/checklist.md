# 检查表

---

## A. 上手前（一次性的）

```
□ 量 6 个几何量：Rw / Lw / ds / S / Lf / Ts
□ 标执行增益 Kexec（发 w 阶跃，读稳态 GyroZ / w）
□ 标电压系数 dv（稳态巡航，读 uq / v）
□ 算最高速度：min( 电压上限, 量化上限 )      ← math.md §5 §6
□ 算每个弯的 e_req / 视场占比                 ← math.md §2
     占比 > 60% 的弯 ⇒ 记下来，那些弯必须降速或必须上前馈
□ 算每个速度下的 wCap，找出瓶颈是内轮还是外轮 ← math.md §4
□ 把赛道几何写成文本文件，算出逐段累计里程
□ 把所有按里程索引的参数改成新里程表
□ 前视延迟 Lf/v 补进所有里程判据
```

**任何一步算出来不满足判据，先解决它，不要跑车。**

---

## B. 每次上车前

```
□ 12V 电池 ≥ 12.0 V          ← 低于 11.5 V 高速段会莫名其妙地摆
□ 只开一个串口程序（无残留进程）
□ 陀螺已标零（c），静止时 GyroZ ≈ 0，sd_z < 0.3
□ 陀螺符号已验（g，车头向左推 GyroZ 为正）
□ 灰度极性已验（压白线为"线"）
□ 电机标定有效（Y 成功过，状态帧一直 R 不是 S/O）
□ 记录仪有空间 / 落盘链路通（发一次 E 再 D 能看到测试记录）
□ 起点摆位：车头方向、初始横向偏移都记录一下（否则下一趟没法对比）
```

---

## C. 每次改完参数

```
□ 只改了一个数（或一组必须同改的数）
□ 算过改动前后的 e_req / ζ / 拍数 / wCap 中至少一项
□ 写下了"预期效果"，跑完能对照
□ 跑完导出逐帧记录
□ 记录行数 ≈ 时长 / Ts        ← 行数少了 = 提前丢线，描述位置是错的
□ 用陀螺积分确认每个转角"真的转够了"
□ 对比改动前后的三个指标：直道摆幅、目标段 e 峰值、出弧瞬间 e 冲量
□ 三项都"不变坏"才保留
```

**不要**在没取数据的情况下连改三个数——那样即使结果变好了，你也不知道是哪个起的作用。

## D. 收尾

```
□ 所有"一次性事件"改成每帧幂等        ← diagnostics §7
□ 钳位写在最后一次赋值之后            ← 搜一遍 变量名\s*= 确认顺序
□ 起跑清状态：arcff / ė / steer / gyroF
     ★ ePrev 用当前读数初始化，不能清 0
□ 停车：写在 vCmd 最终赋值之后
□ 停车后锁状态，防止"停在起跑线上又重新起跑"
□ 飞车保护 / 堵转保护 / 丢线超时停车 —— 三项都实测过
□ 断电重启一次，确认标定（NVS）还在
□ 连续跑三趟，三趟都能跑完     ← 这是"稳定"的定义，不是"跑通一次"
```

## E. 常见"以为好了"的陷阱

| 以为 | 实际 |
|---|---|
| 这趟跑完了 | 可能是丢线后在搜线里蒙过去的（用陀螺积分验） |
| 段二单独验证通过了 | 整车没验证，不等于能跑（四圆区会挂） |
| 直道不摆 | 弧内可能amp 30 mm+，那才是真问题 |
| 降速之后稳了 | 可能是"需求回到了限幅以内"（解饱和），不是"阻尼变好了" |
| 改了参数没效果 | 先确认那个参数真的被用到了（钳位位置/覆盖顺序） |
| 数据里最后一列怪怪的 | 大概率是 `printf` 格式符多了一个 |
| 少了几百行记录 | 车提前丢线了，用户描述的位置是错的 |

## F. 一句话备查

> **摆 → 加阻尼（还相位给 D），不是减刚度。**
> **弯里摆 → 上可算的前馈（`0.90·v/R`），不是调 Kp。**
> **提不了速 → 算电压 / 量化 / 外轮饱和，不是再调参数。**
> **降速 → 不能加阻尼，只能解饱和。**
> **改参数前 → 先取数据，否则是掷骰子。**
