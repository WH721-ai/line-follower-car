# 公式与估算（换车时按这个重算）

> 所有公式都只需要少数几个实测几何量。**不要凭经验给数，算出来。**

---

## 0. 需要先测的 6 个数

| 量 | 符号 | 怎么测 | 本车值 |
|---|---|---|---|
| 轮半径 | `Rw` | 量轮径 / 2 | 0.015045 m |
| 轮距 | `Lw` | 两轮接地点中心距 | 0.144 m |
| 探头间距 | `ds` | 灰度条几何 | 6.7 mm |
| 视场半宽 | `S` | 边缘探头到中心的距离 | 40 mm |
| 前视距离 | `Lf` | 灰度条到轮轴的距离 | 66 mm |
| 控制周期 | `Ts` | 环频率的倒数 | 0.005 s（200 Hz） |

再加两个标定量：

| 量 | 怎么测 | 本车值 |
|---|---|---|
| 执行增益 `Kexec` | 发一个 `w` 阶跃，读稳态 `GyroZ / w` | **0.9007** |
| 电压系数 `dv` | 稳态巡航时读 `uq`，除以 `v` | **10.4 V/(m/s)** |

## 1. 差速运动学

```
ωL = (v − ω·Lw/2) / Rw
ωR = (v + ω·Lw/2) / Rw
```

每 1 rad/s 偏航率需要的轮速差：

```
k_ω = (Lw/2) / Rw = 0.072 / 0.015045 = 4.786
```

---

## 2. 位置环稳态误差（决定"这个弯能不能过"）

```
turn_req = (v/R) / Kexec
e_req    = turn_req / Kp
```

**通过判据**：

```
e_req ≤ 0.6 × S
```

不满足 ⇒ 这个速度过不了这个弯，**不要靠调 Kp 硬塞**（见 §3）。

### 本车参数下的极限

`Kp = 24·v/0.28`，代入得：

```
e_req = (v/R)/0.9007 / (24·v/0.28) = 0.28/(0.9007·24·R) = 0.01295 / R   [m]
```

★ **注意 `v` 消掉了** —— 在 Kp 严格 ∝ v 的设计下，`e_req` **只取决于弧半径**：

| R | `e_req` | 占视场（S=40mm） |
|---|---|---|
| 0.292 m | 44.3 mm | **111%** ❌ |
| 0.342 m | 37.9 mm | **95%** ❌ |
| 0.500 m | 25.9 mm | 65% ⚠️ |
| 0.685 m | 18.9 mm | 47% ✓ |
| 1.000 m | 13.0 mm | 32% ✓ |

> 这张表说明：**在纯 PD 下，R<0.5 m 的弯根本不可能过**（`e_req` 就超视场了）。
> 实际车能过 R292，**完全是因为有前馈**把 81% 的舵量欠出去了。
> ⇒ 前馈不是"优化项"，是**能不能过弯的必要条件**。

有前馈后：

```
e_req_withFF = 0.19 × 0.01295 / R      // 只剩 19%
R = 0.292 ⇒ 8.4 mm（21% 视场）✓
R = 0.342 ⇒ 7.2 mm（18% 视场）✓
```

## 3. 阻尼比

设偏航率环 `ω_cmd = a·turn − b·GyroZ`，位置环 `turn = Kp·y + Kd·ẏ`：

```
特征方程： ÿ + a·Kd·v·ẏ + a·Kp·v·y = 0

ωn = √(a·Kp·v)
ζ  = (Kd/2) · √(a·v / Kp)
```

### 标度律（真正有用的部分）

| 改变 | ζ | ωn |
|---|---|---|
| `v` ↑ | **∝ √v** | ∝ √v |
| `Kd` ↑ | **∝ Kd**（线性） | — |
| `Kp` ↑ | **∝ 1/√Kp** | ∝ √Kp |

### 两条结论

1. **`Kp` 必须严格 ∝ v**，否则 `ζ ∝ 1/√v` ⇒ 一提速就摆。
   ```
   Kp = Kp0 · v / v0
   Kd = Kd0 · √(v / v0)     // 用 √ 是为了不撞量化尖峰上限
   ```
2. **降速不能加阻尼**（`ζ ∝ √v`）。

> ⚠️ 代入本车参数（Kp=54, Kd=12, a=1.6, v=0.70）算得 ζ ≈ 0.86，
> 但实测行为对应的等效 ζ 只有约 0.5。差额来自量化、执行饱和、前视延迟。
> **只用标度律做趋势判断，不要信绝对值。**

## 4. 舵量预算（三层，顺序不能错）

```
wCap = min(
   (v − wDipMin·Rw) / (Lw/2),      // ① 内轮不落进静摩擦死区
   (wheelMax·Rw − v) / (Lw/2),     // ② 外轮不饱和
   yawMax                          // ③ 机械/安全上限
)
```

本车展开：`Lw/2 = 0.072`、`wDipMin = 10`、`wheelMax = 60`、`yawMax = 4.0`

```
wCap = min( 13.889·(v − 0.15045),  (0.9027 − v)/0.072,  4.0 )
```

| v | ① 内轮 | ② 外轮 | 实际 |
|---|---|---|---|
| 0.28 | 1.80 | 8.65 | **1.80** ← 内轮死区是瓶颈 |
| 0.40 | 3.47 | 6.98 | 3.47 |
| 0.60 | 6.25 | 4.20 | 4.20 |
| 0.70 | 7.64 | 2.82 | 2.82 ← 外轮变瓶颈 |
| 0.86 | 9.86 | 0.59 | **0.59** ← 几乎没舵量了 |

> ★ **低速时瓶颈是内轮死区，高速时瓶颈是外轮饱和。** 两个方向的提速都要看这张表。

★ **② 必须用指令速度**，不能用 `max(指令, 实测)`：
降速刚写入时实测还高，用 max 会把舵量锁死（过渡期算成 0.87，而进弯需要 1.5+）。

★ 同时还要过：`v ≤ Kexec · lineTurnMax · R`（舵量不能超过限幅）。

## 5. 电压预算

```
uq ≈ dv · v              // dv 实测 10.4 V/(m/s)
电压余量 = uqLimit − uq
可执行舵量 ≈ 余量 / (每 rad/s 的电压代价)
```

实用判据：**留 15% 余量**

```
v_max = 0.85 · uqLimit / dv = 0.85 × 10.0 / 10.4 = 0.817 m/s
```

> ★ **"跑一段时间才开始摆"是电压特征**：满电时勉强够，电压掉下来就归零。

---

## 6. 量化台阶

```
每格耗时 = ds / v
拍数     = (ds / v) / Ts
```

**通过判据：拍数 ≥ 1.6**

```
ds = 6.7 mm, Ts = 5 ms ⇒  v_max = ds / (1.6·Ts) = 0.8375 m/s
```

> ★ 这个上限和 §5 的电压上限（0.817）**非常接近**——这不是巧合，
> 而是"这台车的硬件决定了它只能跑到 0.8 左右"。想再快必须换硬件
> （更密的灰度、或加前视），调参数没有用。

---

## 7. 前视延迟

灰度条前伸 `Lf`，等价于给位置环一个纯延迟：

```
τ_delay ≈ Lf / v = 0.066 / 0.28 = 236 ms
```

这个延迟**不能忽略**：

- 它让 D 项的相位收益打折 ⇒ 上面的 ζ 公式偏乐观
- 它让所有**基于里程**的判据必须把 `Lf` 补回去（转角授权、降速窗口、四圆区武装）

> 反过来说，如果 `Lf` 太小（探头贴着轮轴），车会"来不及反应"，转角必丢线。
> `Lf` 是被"转角能力"和"延迟"两个方向夹出来的值。

---

## 8. 换车重算清单

按这个顺序算一遍，就得到你新车的全部参数约束：

```
□ 量 Rw, Lw, ds, S, Lf, Ts
□ 标 Kexec（发 w 阶跃读 GyroZ）
□ 标 dv（稳态巡航读 uq / v）
□ 算 §4 的舵量表 ⇒ 找每个速度下的 wCap 瓶颈
□ 算 §5 电压上限、§6 量化上限 ⇒ 取小者为最高速度
□ 算 §2 的 e_req 表 ⇒ 找出视场占比 > 60% 的弯 ⇒ 那些弯必须降速或必须上前后馈
□ 按 §3 给 Kp / Kd（Kp ∝ v，Kd ∝ √v）
□ 算 §7 前视延迟 ⇒ 改写所有里程判据的补偿量
```

**任何一步算出来不满足判据，就不要去跑车**——跑了也一定会失败，
而且失败的现象会误导你往错误方向调。
