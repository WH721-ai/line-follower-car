# 模块一：双驱电机算法

> ESP32 + 2× DRV8313 + 2× MT6701，SimpleFOC **电压模式速度闭环**。
> 对外只暴露一条串口协议：`R<ω左>,<ω右>` 设目标角速度，`S` 读状态。

**职责边界**：这一层只回答一个问题——"轮子有没有转到我要求的角速度"。
它不知道赛道、不知道灰度、不知道偏航率。换掉上层（比如改成遥控车），本模块一行都不用动。

---

## 为什么用速度模式而不是力矩/位置模式

| 模式 | 为什么不选 |
|---|---|
| 力矩模式 | 上层要自己做速度积分，轮子负载一变速度就漂，还要处理打滑 |
| 位置模式 | 里程会累积误差，而且"走 100 mm"和"保持 0.4 m/s"是两种控制目标 |
| **电压模式速度环** | 只用一个编码器就能闭环，抗负载扰动，上层拿到的就是确定的轮速 |

"电压模式"是指 SimpleFOC 的 `motor.torque_controller = TorqueControlType::voltage`
——不做电流闭环，直接输出电压矢量、靠速度环把电压调出来。
**代价**是启动冲击大、低速时电流不可控；**收益**是不需要精确的相电流标定
（本车 M1 那一路根本没有电流采样，见 [HARDWARE](../HARDWARE.md)）。

## 上电必须做的三件事

不做这三件，**一进 RUN 就可能飞车到 120 rad/s 以上**（实测发生过两次）。

```
H1                # ① 板间串口隔离：之后只认 USB 命令
                  #    单板标定前必开！上位机会 20 Hz 灌 R 命令，标定期间完全干扰
Y6,0              # ② 库级 initFOC：自动判方向 + 算零电角度，成功即写 NVS
W140              # ③ 速度目标斜率放到 140 rad/s²
K0.1,1.0,0,10.0   # ④ 速度环 P=0.1 / I=1.0 / D=0 / uq 限幅 10.0 V
```

### 为什么 `Y` 是唯一能救命的命令

`zero_electric_angle`（zea）曾经错过 **204.5°**，后果是：M0 一进 RUN 就飞车到
**123~147 rad/s**，而 `iq` 只有 0.16~0.23 A —— 看起来"有力气但不转"，实际是**力矩整体反向**，
速度环越纠越错，正反馈冲饱和。

`Y6,0` = 用 6 V 电压、对轴 0 跑库级 `initFOC()`：静止锁轴 1.5 s 后反算 zea，
成功即存 NVS，**掉电不丢**。这是唯一能让一个"NOSENSOR 锁死"的轴复活的手段。

> ★ **`A` 命令不判方向**。它是按当前 `dir` 反算 zea 的。如果你猜错了 `dir` 再发 `A`，
> 会得到 3 V / 945 mA 的硬堵转、电机只挪 3.6°（电流全在 d 轴，不产生力矩）。
> **改 `dir` 之前一定先用 `Y` 让库自己判。**

### 为什么 `W140` 是必须的

SimpleFOC 默认 `TARGET_SLEW_RATE = 5 rad/s²`。从 0 爬到 60 rad/s 要 **12 秒**，
表现为"目标下发了但车像硬顶住"，极易误判成硬件故障。发一次 `W140` 就好。

## 命令表（USB 串口 115200，`\n` 结尾，大小写不敏感）

### 日常用

| 命令 | 作用 |
|---|---|
| `R<v0>,<v1>` | 速度模式：设 M0/M1 目标角速度 [rad/s] |
| `R<v>` / `R` | 两轮同速（单参数兼容旧上位机；无参数 = 3.0） |
| `T<u0>,<u1>` | 力矩模式：设 M0/M1 目标 Uq [V]，\|u\| ≤ 10 |
| `S` | 立即停机（目标清零 + 断使能） |
| `Q` | 立即回一帧状态 |
| `K<p>,<i>[,<d>[,<lim>]]` | 在线改速度环 PID |
| `W<n>` | 目标斜率 [rad/s²] |
| `G<tf>` | 速度反馈低通 Tf [s]（0.0002~0.05，默认 0.003） |
| `?` | 帮助 |

### 标定 / 诊断

| 命令 | 作用 | 什么时候用 |
|---|---|---|
| `Y[v][,<ax>]` | **运行时重新对齐 + 解除 NOSENSOR** | 一进 RUN 就飞车 / 堵转不转，**首选** |
| `P[v][,<ax>]` | 实测真实极对数 | 怀疑 pp 设错时 |
| `F[sec][,<ax>]` | 速度反馈体检（均值/标准差/翻转次数/Δ计数直方图） | 判断编码器是不是在抖 |
| `E` | 打印原始传感器读数，绕过开环覆写 | ★**判编码器必须用它**，不能用 `A` |
| `Z` / `Z<a>,<b>` | 打印 / 手工设两轴 zea | 高级调试 |
| `D<a>,<b>` | 手工设 `sensor_direction`（±1） | 方向反了 |
| `N<n>[,<ax>]` | 强制设极对数（默认 7） | 改后该轴 zea 失效，**必须重跑 `Y`** |
| `X` / `X0` / `X1` / `X?` / `Xoff` | 编码器偏心补偿表（256 箱） | 见下「偏心」 |
| `V<v>` / `O<v>` | 闭环 / 开环电压上限 | 开环标定前先降到 2~3 V |
| `L<v>,<ax>` | 开环转（不碰编码器） | **首次接上新电机必做**，验证相序 |
| `B[n][,<ax>]` | 飞行记录仪：存 n 拍到 RAM，停机后倒出 | 查"偶发不转"这类难复现问题 |
| `H0/H1` | 板间串口隔离开关 | 单板标定时 `H1` |

### 状态帧（每 50 ms，IDLE 时 200 ms 心跳）

```
A<a0>,V<v0>,A1<a1>,V1<v1>,S<c0><c1>,I<i0>
  a0/v0 = M0 编码器绝对角 [rad] / 实测角速度 [rad/s]
  a1/v1 = M1 同上
  c0/c1 = 每轴状态：I=IDLE  R=RUN  S=STALL  O=OC(过流)
  i0    = M0 的 Iq [A]（M1 无采样，恒 0）
```

★ **判断"车是不是在动"只看 `vMeas`，不要看 `wL/wR`。**
`S1=II`（两轴 IDLE）时那一对轮速是**陈旧缓存**，而 `vMeas` 一定回到 0.000。

## 上电初始化：四级保险

`initFOC()` 失败会把轴**永久锁死**（`dir = UNKNOWN`、`zea = 未设`、库内已 `disable()`），
之后 `R`/`T` 全被拒绝，`L` 虽然放行但 `move()/loopFOC()` 见 `enabled == 0` 直接 return
⇒ 零 PWM、零电流、零位移，**极易误判成"硬件没电"**，而且没有任何命令能解锁。

所以固件做成了四级：

```
① 复用 NVS 里的 (dir, zea)  ── 上次标定过就直接用，不做运动式判方向（完全可复现）
② 真跑 initFOC()            ── 首次上电或 NVS 缺失时
③ 静态兜底                   ── 提高对齐电压到 6 V + enable() + 重试一次
④ 存盘                      ── 成功即写 NVS
```

**关键设计**：库里的 `alignSensor()` 靠"转一下看有没有动 0.062 rad"来判方向，
这个判定**时好时坏**。而只要 `dir` 已知，就完全可以用"静止矢量反算 zea"跳过运动判定
——这才是可复现的做法。所以第 ① 级最重要：**标定一次，以后每次开机都跳过运动判定**。

## 实际踩过的 7 个坑（复刻时大概率也会遇到）

### 1. 两个电机互相抢 LEDC 通道

原来 LEDC 通道写死 `0/1/2`，第二个 `BLDCDriver3PWM` 实例一创建就把第一个的通道占了。
**修**：按实例分配通道基址（M0 = 0..2，M1 = 3..5）。

### 2. 两个编码器共享 static 变量

`MagneticSensorMT6701SPI::getSensorAngle()` 里的 `last_valid` / `initialized` 是
**函数内 static** ⇒ 两个实例共享同一份状态，一个轴的跳变污染另一个轴。
**修**：改成成员变量。

### 3. 同一个 SPI 外设重复 begin()

每个编码器实例各自 `SPIClass(VSPI)` 各自 `begin()`。两个 MT6701 共用 SCK/MISO
（只有 CS 不同），重复初始化会打架。
**修**：全局限一次、共享一个 `SPIClass`。

### 4. `ledcAttachPin()` 早于 `ledcSetup()`

报 `E (120) ledc: LEDC is not initialized`。**修**：严格先 setup 后 attach。

### 5. ★ 编码器读数"永久锁死"

一次 SPI 受扰读出 `Δcnt = 8192`（恰好 π，低 13 位不变只翻最高位）的假跳变，
旧逻辑 `if(diff>π && !crossing) return _last_valid;` 且**不更新** `_last_valid`
⇒ 假跳变持续出现 ⇒ 读数永远停在旧值 ⇒ `v ≡ 0` ⇒ 速度环把 uq 顶到限幅灌 1.4 A ⇒ **不转**。
**修**：加连续异常计数，最多连丢 2 拍，**第 3 拍无条件接受**。

> 这一点很重要：**任何"丢弃异常读数"的逻辑都必须有强制接受兜底**，否则一个持续异常就死锁。

### 6. ★ 编码器磁铁偏心

MT6701 磁铁/芯片偏心 → 编码器角带**每机械转一次的正弦误差**，机械角振幅 ±19.5°
（= ±136° 电角度）。开环换相角是时间积分、不读编码器，所以**开环正常**；
闭环 `elecAngle = norm(dir·pp·θ_enc − zea)` 直接吃进这个误差 ⇒ 每转里两次把换相矢量
推偏过 ±90° ⇒ 力矩周期过零/反向 ⇒ 电机激荡。

**修**（`X` 命令）：用开环磁场角当精确时钟测误差
```
err = normalize(dir·pp·θ_enc − pp·θ_shaft)
```
按 `θ_enc` 分 256 箱取均值、取负作补偿表，在 `getSensorAngle()` 里加回去，表存 NVS。
标定完**要重跑 `Y`/`A` 重标 zea**（此时 zea 是在补偿后的角度上算的）。

### 7. 速度环 P 不能大

`P = 0.2` 时，35 rad/s 的误差就打满 7 V ⇒ **bang-bang 极限环**。
`P = 0.1` 后翻转帧 10→0、`iq` 降 4.5 倍。**P/I 绝不能动**，这是实测定案值。

## 关于 `iq` 虚高（不要被吓到）

固件报 `iq ≈ 1.65 A` 而台面电源（12.02 V / CV 模式）只取 0.49 A
⇒ 固件功率 `1.5·uq·iq ≈ 13.6 W` > 输入 `5.9 W`，**物理不可能**
⇒ **`iq` 采样虚高约 2×**，所谓"硬启动过流"是采样伪报警。

按 KV 反解：`K_V = 100 rpm/V = 10.47 rad/s/V`，用它算出来的真实电流只有 ~1.0 A。
**修**：采样增益 50 → 90（= 50×1.8，按 1.8 保守修正，宁早跳不晚跳），
OC 判据改用 `iq_filtered` + `OC_CONFIRM_COUNT` 5→10。

## 编译

```bash
cd motor-control
pio run -e esp32dev              # 编译
pio run -e esp32dev -t upload    # 烧录
pio device monitor -b 115200     # 看日志
```

- 平台钉死 **espressif32@7.0.1 / Arduino core 2.0.17**——这是拿分的固件实际用的组合，
  换版本会改 LEDC / ADC 行为，可能导致标定失效。
- `lib/SimpleFOC` 已内置于仓库（MIT），**不需要联网装库**，保证版本可复现。
- 厂商的 `libSF_Motor.a` / `libSF_Communication.a` 是**预编译闭源库**，
  本仓库**不包含**、也不需要（当前固件是自写 SimpleFOC 实现）。
