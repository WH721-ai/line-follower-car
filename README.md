# 双轮差速循迹小车 · 完整开源实现

> 一台自己写控制律、自己标定电机、自己调参数的循迹小车。
> 在 2026-10 的比赛中跑完 **37.02 m 完整赛道**（含六段弧、十字、四圆区、5 个直角），
> 自动停回起点区，得分 **92.5 / 100**。
>
> 作者：**WH721-ai** · 许可：MIT

这个仓库不是"调好的代码打包"，而是**可复现的方法**：两台 MCU 各管一件事，两块算法各自独立可编译，
参数从哪里来、为什么这么取、踩过哪些坑，全部写进文档。

## 一句话架构

```
        ┌──────────────────────────── ESP32-S3 扩展主控（循迹算法）────────────────────────────┐
        │                                                                                      │
  7 路灰度 ──→ 位置 e ──→ PD + 曲率前馈 ──→ 目标偏航率 ω_ref ──→ 偏航率环 ──→ 差速运动学      │
  (IO14/47/38/40/41/21/48)        ↑                        ↑        │                        │
                                  │                    MPU6050      │ ωL, ωR                 │
                            航向保持环（直道）        (I2C 0x68)     ↓                        │
        └───────────────────────────────────────────────────────────┼────────────────────────┘
                                                                     │ UART @2 Mbps
                                                          R/T 协议   │ (GPIO17/18)
        ┌────────────────────────────────────────────────────────────┼────────────────────────┐
        │                          ESP32 电机主控（双驱电机算法）    ↓                        │
        │  M0：SimpleFOC 速度闭环 ← MT6701 磁编码器（SPI）  DRV8313 三相功率级                 │
        │  M1：SimpleFOC 速度闭环 ← MT6701 磁编码器（SPI）  DRV8313 三相功率级                 │
        └──────────────────────────────────────────────────────────────────────────────────────┘
```

**分层的关键**：上层只算"车体要多少线速度、多少偏航率"，绝不碰电机电流；
下层只保证"轮子转到你要的角速度"，绝不关心赛道。两层之间只有一条 **2 Mbps 的 ASCII 协议**
（`R<v0>,<v1>` 设速度 / `S` 读状态 / `T` 力矩模式），任何一层单独换掉，另一层不用改。

## 快速开始

### 0. 环境

```bash
pip install platformio          # 或装 VS Code 的 PlatformIO 插件
```

### 1. 编译并烧录两个模块

```bash
# 模块一：电机主控（ESP32，USB 调试口 115200）
cd motor-control
pio run -e esp32dev -t upload

# 模块二：循迹主控（ESP32-S3，原生 USB 口 921600）
cd ../line-following
pio run -e esp32-s3-devkitc-1 -t upload
```

两个模块**完全独立**，可以单独编译、单独验证——这是刻意的设计，见下面第 3 条。

### 2. 第一次上电必须做的事

**电机侧**（否则一进 RUN 就可能飞车）：

```
Y6,0          # 库级 initFOC，自动判零电角度并写 NVS，成功一次以后不用再做
W140          # 速度目标斜率放到 140 rad/s²（默认 5，从 0 到 60 要 12 秒）
K0.1,1.0,0,10.0   # 速度环 P 只能是 0.1；uq 限幅 10.0 V
```

> ⚠️ **`A` 命令不判方向**，它是按当前 `dir` 反算零电角度的。改 `dir` 之前一定先用 `Y` 让库自己判。

**循迹侧**：

```
c             # 重标陀螺零偏（车必须静止放平，阻塞约 5 秒）
g             # 陀螺自检 3 秒：手推车头向左，GyroZ 必须为正；反了就翻符号
```

### 3. 为什么分成两个模块

因为它们**坏了要分开排查**。整机联调时最常见的情况是"车走不直 / 转不过弯"，
如果电机闭环本身不准，你在上层调一辈子参数都是白费。所以：

- 先让 `motor-control` 单独跑通：架空，串口发 `R20,20`，两轮应稳定在 20 rad/s，
  `iq` 平稳、无 STALL、无翻转帧；
- 再让 `line-following` 单独跑通：可以把车推着走，看灰度读数与陀螺符号对不对；
- 最后才联调。

## 赛道

```
        L1                          L2        A1(90°)
   ┌──────────────────────────────┐
   │  S(起点/终点)                │ R1~R6 六段弧 R200
   │  L12 = L1 共线 ⇒ 终点无横线   │
   └──────────────────────────────┘
                 ... 见 track/README.md
```

全程 **37 019.6 mm**，共 12 段直线 + 24 段圆弧 + 5 个原地直角。
关键点：

- **六段 R200 弧**（2.3~6.67 m）：半径最小、最密，速度被 `v ≤ 1.45·R` 卡死在 0.28 m/s
- **段二 6.67~22.94 m**：全是圆弧（R500/R685/R342/R292/R392/R600…），**有两个十字但没有直角**
- **四圆区 22.94~26.76 m**：R300 四连圆，右-左-右-左各 180°，靠灰度"分叉签名"判切点
- **A2~A5**：五个原地直角，靠里程授权 + 横边检测
- **终点 = 起点**：`L12` 与 `L1` 是同一条直线 ⇒ **终点没有任何横线标记**
  ⇒ 停车只能按里程（`LINE_STOP_ODO_MM`）

## 四个"想明白就不走弯路"的核心结论

整个项目最耗时间的不是写代码，是**在错误的方向上反复调参**。下面四条是花了最多代价换来的，
`docs/DEBUG_PLAYBOOK.md` 里每一条都有实测数据支撑。

### 1. 「摆」= 阻尼不足，不是刚度太大

车在直线上左右画龙，第一反应都是"增益太大了，降一点"。**这是错的。**
降 Kp / 降 boost / 加低通滤波，全都是在减刚度或加滞后，结果是摆变"慢而大"，永远不会消失。

**一句话判据**：降增益后**幅度变小但周期变长** ⇒ 刚度问题；**几乎没变化** ⇒ 阻尼不足
⇒ 唯一正解是**还相位给 D**。压噪要用**限幅**，不要用**低通**（6.7 mm 量化台阶的毛刺
是 1.34 m/s，真实 ė 不超过 0.36·v，差 4~9 倍，限幅可以零相位代价地削掉它）。

### 2. 弧内一定要有前馈，而且可以**直接算**，不用学

位置环是 type-0 的：要在圆弧上维持曲率，**必须常驻一个横向偏差** `e_needed = (v/R)/0.9007/Kp`。
R292@0.42 要 29.6 mm，而七路灰度视场只有 **±40 mm** ⇒ 光"待在那儿"就吃掉 74% 的视场，
剩给扰动的余量不到 10 mm，一个量化台阶就出界。

所以弧内**必须**有前馈把常值舵量直接欠出去。而这个前馈**不需要学习**：

```
arcff = sgn · 0.90 · (v / R)
```

实测 R7@0.50 前馈稳态 = 0.90，公式给 0.90×(0.50/0.500) = 0.90，**一个数不差**。

### 3. 千万不要用降速换稳定

`ζ ∝ √v`（Kd 固定时）——降速会让阻尼**更差**、周期更长、单次摆幅更大。
这一条是用户实测否掉的：把弯道速度全降 15%，结果是"跑得更差了"。

### 4. 比赛要的是"跑完"，不是"某一段快"

项目里有一整条提速线（段二 0.40 → 0.86 m/s）单独验证全部通过，
但拼回全程后四圆区那个末尾右转角就是过不去，最终整条线回滚。
**最终拿分的版本是"最慢但最稳"的那一版。**

## 给想复刻的人

最短路径：

1. 按 [`HARDWARE.md`](./HARDWARE.md) 买件，先把**电机模块架空跑通**（这一步不通过不要往下走）；
2. 把赛道几何换成你自己的——`track/field_track_named.geom` 是纯文本，改完用
   `line-following/tools/_map_len.py` 重新算一遍逐段累计里程；
3. 把所有 `LINE_CORNER_MM` / `SEG2_ARC` / `SEG2_SLOW` 的里程按你算出来的表改一遍
   （**这是唯一必须改的地方**，它们是地图里程硬编码）；
4. 按 [`docs/TUNING_GUIDE.md`](./docs/TUNING_GUIDE.md) 的顺序调参，**每一步都取数据**，
   不要"改一个数跑一趟看看"——那是掷骰子。
