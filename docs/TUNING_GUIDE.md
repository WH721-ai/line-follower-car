# 调参顺序（照着做，不要跳步）

> 这份文档的每一条"不要跳步"都是因为跳过之后**一定**会在后面某个地方卡住，
> 而且症状看起来和真正的原因毫无关系。
>
> 每一步都有**通过判据**。不通过就不要往下走。

---

## 步骤 0：环境与电源

| 检查 | 方法 | 通过判据 |
|---|---|---|
| 12 V 电池 | 万用表量主电源 | ≥ 12.0 V（低于 11.5 V 会在高速段莫名其妙地摆） |
| 逻辑 5 V / 3.3 V | 量模块输入 | 正常 |
| 串口能通 | 发 `s` 或 `?` | 有回显 |

> ★ **12 V 没开 ⇒ 两块板状态全零、两轴完全不动。**
> 排查"车不动"时，第一件事永远是量电源，不是看代码。

★ **只允许一个程序占用串口。** 重复启动监听会抢帧 ⇒ 半行截断、时间戳乱跳。
启动前先查一遍有没有残留的 python / 串口助手进程。

---

## 步骤 1：电机层（架空，不落地）

**目标**：两个轮子都能稳定转到任意给定角速度。

```
H1                # 板间串口隔离（单板标定必开！上位机会 20 Hz 灌命令）
Y6,0              # 自动判方向 + 算零电角度，成功写 NVS
Y6,1              # 第二轴同样
W140              # 目标斜率放开（默认 5 rad/s²，爬到底要 12 秒）
K0.1,1.0,0,10.0   # 速度环 P=0.1 / I=1.0 / uq 限幅 10 V
R5,5              # 两轮 5 rad/s
R20,20
R40,40
S
```

**通过判据**（全部满足才算过）：

| 判据 | 说明 |
|---|---|
| 每个目标速度都**稳稳停住不抖** | 而不是"大致转到" |
| 状态字符一直是 `R`（RUN） | 出现 `S`（STALL）或 `O`（过流）就是没过 |
| `iq` 平滑、无尖峰 | `M1` 那路没有电流采样，恒 0 是正常的 |
| 用手轻捏轮子加负载，速度能回来 | 说明速度环真的在闭环 |
| **零点几秒内就到位**，不是慢慢爬 | 慢爬说明 `W` 没设 |

### 不通过时按顺序查

1. **一进 RUN 就飞车（123~147 rad/s）而 `iq` 只有 0.2 A** ⇒ 零电角度错（力矩反向）。
   发 `Y` 重标，别发 `A`。
2. **完全不转、`iq` 也几乎 0** ⇒ 可能轴被"NONSENSOR 锁死"了。
   发 `Y` 复活。**注意 `A` 命令不判方向**，方向猜错再 `A` 会得到硬堵转。
3. **有电流但不转（`iq` 1.4~1.6 A、`uq` 顶满）** ⇒ 三条可能：
   - 编码器偏心（发 `X` 建补偿表，然后重跑 `Y`）
   - 编码器读数被"永久锁死"（看 `E` 打印的原始读数是不是恒不变）
   - 速度环 P 太大（必须是 0.1，0.2 会 bang-bang）
4. **目标到不了** ⇒ 先查 `W` 斜率，再查 `uq` 限幅。

> ★ **这一步不过，后面所有工作都是白费。** 我们在这里花了两整天，
> 后面所有"车走不直 / 转不过弯"的现象里，有一半根因在这里。

## 步骤 2：传感器层（车架空或手推）

### 2.1 灰度符号与顺序

```
d1                # 开状态帧
```

手动把车横着推过白线，看 7 路读数（或解算出来的 `e`）：

| 检查 | 通过判据 |
|---|---|
| 顺序对不对 | 从左往右扫，亮的通道必须按顺序变化（不能跳号） |
| 极性对不对 | 压白线 = 亮。如果是反的，改解算里的极性 |
| `e` 的符号 | 线偏右时 `e` 应该是**正**（或负，但必须与转向指令一致） |
| 视场边界 | 推到最边上时 `e` 应该接近 ±40 mm |

### 2.2 陀螺符号与零偏

```
c                 # 重标零偏（车静止放平，阻塞约 5 秒）
g                 # 自检 3 秒：手推车头向左
```

| 检查 | 通过判据 |
|---|---|
| `GyroZ` 符号 | 车头向左推 ⇒ `GyroZ` **为正**。反了要改符号，**不是改参数** |
| 静止零偏 | 静止时 `GyroZ` 应该 ≈ 0（< 0.02 rad/s） |
| 方差 | `[CAL]` 里 `sd_z` 应该 < 0.3，否则标零不可信，重新标 |

> ★ 陀螺零偏如果偏 0.05 rad/s，偏航率环会把它翻译成"车在转"⇒ 持续往一个方向打舵。
> 这就是为什么 `|turn|` 极小时要**门控掉陀螺反馈**（见下）。

### 2.3 里程标定

推着车沿一条已知长度的直线走，读里程增量：

| 检查 | 通过判据 |
|---|---|
| 线性度 | 走 1 m 和走 3 m，误差比例应一致 |
| 绝对值 | 误差应在 **−2% ~ −4%**（负漂移是正常的，来自轮子滑移） |

**记下这个漂移比例**——后面所有按里程的判据都要用它换算。

---

## 步骤 3：第一次闭环（低速直道，落地）

**目标**：车能以 **0.15~0.20 m/s** 沿直线走 2 米不丢线。

```
v0.18
```

先用**最低速度**。这一阶段只验证"符号全对、能跟住线"，不谈性能。

**通过判据**：

- 能走完 2 m，中途不丢线
- 走完时车头方向与线的夹角 < 10°
- 没有"往一边持续偏"（那是陀螺零偏或轮子不对称）

**不通过**：

| 症状 | 原因 |
|---|---|
| 一启动就往一边甩 | 轮子起步不对称 ⇒ 开航向保持（直道 `kh`） |
| 越走越偏、不纠 | `e` 符号反了，或 `Kp` 太小 |
| 一走就剧烈左右摇 | `Kd` 太大撞上量化尖峰，或 `Kp` 太大 |

---

## 步骤 4：直道调稳（这是最容易走错方向的一步）

**目标**：0.28 m/s 直道走 3 米，摆幅 ≤ ±1 个量化格。

### 调参顺序：**先 P，再 D，最后才是限幅**

```
1. 把 D 置 0
2. 慢慢加 P，加到"刚开始有点摆"为止 —— 记下这个 Kp_crit
3. 把 P 退回 0.6·Kp_crit
4. 加 D：从 0 开始，每次 ×1.5，直到摆幅明显下降后不再下降
5. 如果 D 加到很大仍然摆 ⇒ 不是 D 不够，是限幅在钳它（见下）
```

### 判据：降增益后幅度变小但周期变长 ⇒ 刚度问题；几乎没变化 ⇒ 阻尼不足

**这一条必须用数据判断，不能靠眼睛。** 导出逐帧记录，看：

| 指标 | 怎么读 |
|---|---|
| 摆幅 | `e` 的峰峰值 |
| 周期 | 相邻两个峰值的时间差 |
| 过零次数 | 越多越"抖" |
| `wCmd` 幅值 | 是否一直在 ±0.9 来回翻（打满了） |

判读表：

| 现象 | 结论 |
|---|---|
| ±1 格（6.7 mm）/ 350~500 ms | **量化极限环**，调参无用，只能降速或加前视 |
| ±3 格以上 / 650~900 ms | 闭环振荡，增益/阻尼问题 |
| ±2~3 格 / > 1.2 s | 机械问题（轮径不一致/阻力/灰度条装歪）或陀螺零漂 |
| `wCmd` 只在 ±0.2 就摆 | **不是增益问题**，查机械 |

### 限幅这一项要算，不要猜

```
sinθ_clamp = 限幅值 / v
```

这个角度必须**大于你的实际摆幅角度**，否则 D 项被钳死、P 还在长 ⇒ 等效相位滞后 ⇒ 发散。
**改速度时必须重算这个值。**

## 步骤 5：圆弧（前馈是必须的，不是优化）

**目标**：过最紧的那个弯不丢线。

### 5.1 先算，不要试

```
arcff = sgn · 0.90 · (v / R)
```

同时确认这条弧**允许在这个速度过**：

```
① 舵量需求 v/R ≤ lineTurnMax · 执行增益  = 2.00 × 0.9007 = 1.80 rad/s
② 外轮不饱和：v/Rw + (v/R)·Lw/(2Rw) ≤ wheelMax
③ 稳态偏差 e_req = (v/R)/0.9007/Kp ≤ 0.6 × 视场半宽
```

三条都过才敢跑。**第 ③ 条是"这个速度到底行不行"的决定性判据**，
不要用"上次这个弯过了"来判断。

### 5.2 前馈要每帧赋值，不要一次性投递

```c
// 弧内，每帧
if (onArc) {
    lineArcFF = sgn * 0.90f * (lineRunV / R);
}
```

★ **不要**用"进弧那一帧 arm、下一帧消费"的写法——实测 100% 不生效。

### 5.3 前馈有值之后，boost 必须让位

大偏差补舵（boost）和前馈是重复补偿。前馈一旦建立（`|arcff| > 0.8`），
boost 必须线性淡出到 0，**否则两者叠加必过转**。

### 通过判据

- 弧内 `e` 的峰值 ≤ 0.6 × 视场半宽
- 出弧瞬间 `e` 不冲过 40 mm（**出弧是需求舵量最大的时刻**，注意别在那一刻切档降权限）
- 用**陀螺航向积分**确认"真的转够了角度"（不要用"这趟跑完了"当成功）

---

## 步骤 6：转角

**目标**：每个 90° 转角转完能重新找到线。

调参顺序：

1. **先只开"里程授权"**：确认车在经过转角点时不乱转（说明没有误触发）
2. **再开横边检测**：确认在转角点能触发
3. **最后调去抖时间和前进距离**

| 参数 | 影响 |
|---|---|
| 去抖时间 | 太短会误触发（十字/污渍），太长会漏触发 |
| `L_f` 前进距离 | 太短：轮轴还没到转角点就转 ⇒ 转完偏出去；太长：冲过转角点 |
| 原地转的舵量 | 必须 ≤ `lineTurnMax` |

### 铁律

> **漏判只少转一个弯，误判直接出赛道。宁可不转，也不要乱转。**
>
> 所以：**授权窗口外的横边命中一律撤销**，哪怕看起来很像。

★ 如果赛道上**有十字路口**，那段必须**整体禁用转角判据**——
十字的灰度签名和直角完全一样，无法区分。

---

## 步骤 7：速度（可选，而且风险最高）

**只有在步骤 3~6 全部通过、并且有整跑验证余量时才做。**

### 必须遵守的顺序

1. **一次只改一段弧的速度**
2. 改完**跑一趟**
3. `D` 导出逐帧记录
4. 确认三件事都变好或不变坏：
   - 直道摆幅（应该不变，因为直道增益不该受影响）
   - 该弧内的 `e` 峰值（应该下降或持平）
   - **出弧瞬间的 `e` 冲量**（最容易变坏的指标）
5. 通过才动下一段

### 必须同时改的东西

| 改了 | 必须同时改 |
|---|---|
| `v` | `Kp ∝ v`（否则 `ζ ∝ 1/√v` 必降阻尼） |
| `v` | `ė` 限幅 ∝ v（否则 D 被钳死） |
| `v` | 重新核算 `wCap` 外轮项、电压余量、量化"每格几拍" |
| 提高 `wheelMax` | **当作"增益放大 30%"处理**，重新核算环路增益 |

### 一条血泪教训

> 我们曾经有一条提速线：段二从 0.40 提到 0.70 再到 0.86，
> 配了逐弧降速表 + 曲率前馈 + 禁止转角判据。
> **段二单独验证全部通过。** 拼回全程后，四圆区末尾那个右转角就是过不去。
> 最后整条线回滚，比赛用的是最慢最稳的那一版。
>
> **"段二跑通了"不等于"整车跑通了"。整跑验证不能省。**

---

## 步骤 8：收尾

| 项 | 做法 |
|---|---|
| 消抖 | 把所有"一次性事件"改成每帧幂等（见 PLAYBOOK 4.2/4.3） |
| 起跑清状态 | 清 `arcff` / `ė` / `steer` / `gyroF`；但 `ePrev` **用当前读数初始化，不能清 0** |
| 记录落盘 | 确认停稳后能自动写 flash，`D` 能导出来 |
| 停车点 | 按里程停，**只改一个数**：停早了调大、停晚了调小 |
| 兜底 | 飞车保护 / 堵转保护 / 丢线超时停车 全部实测一遍 |

## 附：一张"我现在该做什么"的流程

```
车不动？
  └─ 量 12V → 发 Y 重标 → 查 NONSENSOR / 编码器锁死        [步骤 1]

能动但走不直？
  └─ 架空验两轮速度一致性 → 开航向保持 → 查陀螺零偏         [步骤 3]

直道摆？
  └─ 先取数据！看周期和 wCmd 幅值                          [步骤 4]
     ├─ ±1 格 / 短周期 → 量化极限环（调参无用）
     ├─ 大幅 / 长周期   → 增益阻尼（P↓ 或 D↑）
     └─ wCmd 很小仍摆   → 机械 / 陀螺零漂

弯里摆、直道不摆？
  └─ 算 e_req/视场 → 加前馈（不要降速！）                   [步骤 5]

某个里程冲出去？
  └─ 查那段有没有十字 → 禁用转角判据 → 查降速窗口缝隙        [步骤 6]

提速后就摆？
  └─ 重算环路增益 / 限幅按速度缩放 / 电压余量 / 每格几拍      [步骤 7]
```
