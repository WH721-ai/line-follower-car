# 模块二：循迹算法

> ESP32-S3 + 7 路灰度 + MPU6050，**200 Hz** 控制环。
> 输入是 7 个数字量，输出是左右轮目标角速度。

**职责边界**：这一层只回答"车该往哪走、该给多少偏航率"。
它不知道电机怎么换相、不知道电压够不够——那些由
[模块一](../motor-control/) 保证。

---

## 一、一帧 5 ms 里发生了什么

```
读 7 路灰度 → 解算横向偏差 e [mm] → 判断线是否可信（连续性/路型）
                                        │
                        ┌───────────────┴───────────────┐
                        │                               │
              位置环 PD + 曲率前馈                丢线 → 搜线 / 转角状态机
                        │                               │
                 lineSteer [rad/s]                       │
                        └───────────────┬───────────────┘
                                        ↓
                          偏航率指令 turn = lineSteer
                                        ↓
                     wCmd = 1.6·turn − 0.6·GyroZ      （偏航率环，陀螺做阻尼）
                                        ↓
                     ωL = (v − wCmd·Lw/2) / Rw         （差速运动学）
                     ωR = (v + wCmd·Lw/2) / Rw
                                        ↓
                        UART @2 Mbps → R<ωL>,<ωR>
```

## 二、灰度位置解算

7 路数字量，**白线版**：压白线为 `0`，压黑底为 `1`。所以"线"= 连续的 0 段。

```
探头位置（mm）： -40  -26.7  -13.4   0   +13.4  +26.7  +40
                 OUT1  OUT2  OUT3  OUT4  OUT5  OUT6  OUT7
                   最左  ←    ←   中心   →     →   最右
```

- **探头间距 6.7 mm** ⇒ 位置量化台阶 **6.7 mm**
- **视场 ±40 mm**（边缘探头中心）
- 解算：取连续 0 段的**加权中心**（`n` 个探头亮时取均值）
- `lineValid` 要求 `n ∈ [1,3]`；`n = 0` 或离散假位型 = **真丢线**；`n ≥ 4` = **饱和**（十字/大块黑）

### 为什么 `n ≥ 4` 不能"保持上一次值"

试过保持 —— 结果是车带着 9.5° 的偏角一直画弧冲出场外。现在 `n ≥ 4` 时让 `e`
以 τ = 0.3 s 的速率回零（"线在正中"的假设），而不是保留旧值。

### 66 mm 前视的代价

灰度条装在车头**前伸 66 mm**，所以解算出来的是"车头 66 mm 处"的偏差，
不是车身中心的。这等价于给整个位置环引入纯延迟 `66/v` 秒
（0.28 m/s 时约 **0.24 s**）。

这不是纯缺点：前视本身就提供相位超前。但所有**基于里程的判据**
（转角授权、降速窗口、四圆区武装）都必须把这个 66 mm 补回去，否则判据永远晚一步。

## 三、控制律

### 3.1 位置环：PD + 曲率前馈

```c
// 纯 PD（不含 trim / I / 前馈）
lineSteer = lineSign * (Kp·e + Kd·ė)

// ė = de/dt，先差商再低通（τ = 120 ms）
// τ 不能更大：R200 弧上 0.45 s 就可能丢线，200 ms 的滞后等于直接失败

// 曲率前馈
lineArcFF = sgn · 0.90 · (v / R)

// 最终舵量
turn = constrain(lineSteer + lineArcFF + boost, ±lineTurnMax=2.00)
```

**为什么 D 是主角**：P 只能对"已经偏了多少"反应；D 对"正在以多快速度横滑"反应。
起步 13° 偏斜时 `e` 才 6.7 mm（P 只给 0.09 rad/s），但 `ė ≈ 0.078 m/s`
⇒ D 直接给 **0.62 rad/s**。**这才是能在出视场之前把车掰回来的那一项。**

**为什么必须有曲率前馈**：位置环是 type-0 的——要在圆弧上维持曲率，
必须常驻一个横向偏差 `e_needed = (v/R)/0.9007/Kp`。视场只有 ±40 mm，
而 R292@0.42 需要 **29.6 mm**（吃掉 74% 视场）⇒ 光"待在那儿"就没余量抗扰动了。

前馈**不需要学习，直接算**：稳态时 `GyroZ ≈ v/R`，所以

```
arcff = sgn · 0.90 · (v / R)
```

钉 `0.90` 而不是 `/0.9007`：执行增益是 0.9007，钉 0.90 意味着前馈只出 **81%** 的所需舵量，
剩下的 19% **刻意留给位置环**（`e ≈ 3~6 mm`）。钉满会让位置环空转、失去纠偏能力。

> 完整推导（阻尼比、环路增益、可执行舵量、电压墙）见
> [`docs/CONTROL_THEORY.md`](../docs/CONTROL_THEORY.md)。

### 3.2 偏航率环：陀螺做阻尼

```c
wCmd = 1.6·turn − 0.6·GyroZ
```

**注意系数 1.6**。因为门控 `TURN_GATE_LO/HI = 0.01/0.04 rad/s` 极低，
**直道也走这条式子**（不是只有转弯才走）。所以

> ★ **直道的真实环路增益是 `Kp × 1.6`，不是 `Kp`。**

这一条如果算错，所有关于"为什么这个速度能跑、那个速度就摆"的分析都会偏 60%。

### 3.3 直道航向保持

`|turn| < 0.02` 且 `|forward| > 0.005` 时，位置环不工作（线在正中，`e = 0`），
此时是**纯开环**——左右轮任何不对称都 1:1 变成航向漂移。实测起步 1 s 内甩 22.4°。

所以直道切换到一个独立的航向环：

```c
wCmd = kh·eYaw + holdI − kd·GyroZ      // kh=2.0, kd=0.25, ki=0(默认关)
```

`GyroZ` 项**只做阻尼、不引入零偏偏置**。

### 3.4 差速运动学 + 三道限幅

```c
ωL = (v − wCmd·Lw/2) / Rw
ωR = (v + wCmd·Lw/2) / Rw
```

限幅有三层，**层级不能错**：

| 限幅 | 值 | 物理含义 |
|---|---|---|
| `lineTurnMax` | 2.00 rad/s | 隐含最小可跑半径 `R_min = v/2.00` |
| `wCap` | `min(13.889·(v−0.15045), (wheelMax·Rw − v)/0.072, 4.0)` | 第二项是**外轮不饱和**约束 |
| `wDipMin` | 10.0 rad/s | 内轮最低转速，防静摩擦死区 |

★ `wCap` 第二项**必须用指令速度**，不能用 `max(指令, 实测)`：
降速刚写入时实测速度还高，用 max 会把舵量锁死。

**`wDipMin` 为什么存在**：偏航率环 `wCmd = turn + kt·(turn − GyroZ)` 在打滑时会与实测**反号**
⇒ 自我放大：内轮掉进静摩擦死区不转 ⇒ 车真的绕内轮枢轴转 ⇒ `GyroZ` 更反向 ⇒ `wCmd` 更负。
实测跑到过 **17.8 圈**。钳住"内轮速 ≥ `wDipMin`"就切断这条正反馈。

## 四、速度体系

这台车只有**两档巡航速度**，加两个区间专用速度。没有逐弧降速表——那是提速线的做法，
已验证在整车联调下不成立（见本节末尾）。

| 段 | 里程 | 速度 | 由谁决定 |
|---|---|---|---|
| 段一：起跑 + 六段 R200 弧 | 0 ~ 6.70 m | **0.28** m/s | `autoRunV` |
| 段二：R500~R600 长弧群 | 6.70 ~ 22.94 m | **0.40** m/s | `lineV2`，`lineV2Odo = 6700` 处提档 |
| 段三：四圆区 | 22.94 ~ 26.76 m | **0.28** m/s | `C4_V`（区内强制） |
| 出四圆区 → A2 → 段四 | 26.76 ~ 37.02 m | **0.25** m/s | `C4_EXIT_V` → 段四巡航 |

**提档是一个双门 + 500 ms 去抖的**一次性**动作**（`lineV2Done`）：
里程过了 `lineV2Odo` **且** 已经在弧外稳定跟线，才把 `lineRunV` 从 0.28 抬到 0.40。
之后不再回退——**必须是有去无回的单向开关**，否则会在 6.7 m 附近反复抖。

> ★ **段二 0.40 m/s 是这台车能跑完全程的主要原因之一**：速度越低，
> R7~R15 的舵量余量和阻尼都越宽松。
>
> 曾经有一条提速线（段二 0.40 → 0.70 → 0.86，配逐弧降速表 + 曲率前馈 + 禁转角判据），
> **段二单独验证全部通过**，但拼回全程后四圆区那个末尾右转角就是过不去，
> 最终整条线回滚。**比赛要的是跑完，不是某一段快。**
>
> 如果你想把速度提上去，正确顺序是：
> 1. 一次只改**一段弧**的速度 → 跑一趟 → `D` 取逐帧记录 → 确认直道/弧内幅度都变好；
> 2. 整跑验证（这是关键，不能只验段二）；
> 3. 再动下一段。
>
> 提速线那些配方没有随仓库发布，因为它**没有通过整跑验证**，不该被当成可用的东西。

### 速度的三条硬约束

1. **电压墙**：`uq ≈ 10.4·v`（0.84 m/s 实测 8.74 V），S1 限幅 10.0 V。
   剩余电压才变成"额外轮速"，也就是可执行舵量 ⇒ **上限 0.86 m/s**。
2. **外轮不饱和**：`外轮 = v/Rw + ω·Lw/(2Rw)`。`wheelMax = 68`，0.92 m/s 时基础轮速就贴顶
   ⇒ 只剩内轮 ⇒ 单向转向 ⇒ 锯齿摆。
3. **量化台阶**：6.7 mm 台阶在 200 Hz 下，0.86 m/s 时**一帧只走 1.56 拍**。
   小于 1.6 拍时一帧可能跨一格，差商直接出 1.34 m/s 的假速度。

## 五、转角：四层判据

全程有 5 个原地直角（A1~A5）。判"要转弯"用了四层，任何一层不满足都不转。

```
① 底层横边检测
   edgeR = ((b & 0x78) == 0x78) && ((b & 0x03) != 0x03)     // 右侧 4 路全黑 + 边缘不是全黑
   edgeL = 对称
   20 ms 去抖 + 上膛（arm）

② 里程授权表
   LINE_CORNER_MM[5] = {2300, 26762, 27045, 27885, 34720}   ±1300 mm
   窗外一律撤销            ← 判错代价不对称：漏判只少转一个弯，误判直接出赛道

③ 已知转角压线即转
   跳过 300 ms 观察窗，DEG = {0, -90, -90, 0, +90}

④ 前进 L_f = 66 mm（0.15 m/s）→ 原地转 → 重新找线
```

★ 第 ② 层是**授权表**而不是"数第几个弯"：全部按地图累计里程索引，
所以 `ODO_START_MM` 一个宏就能让车从中途任意位置起跑。

★ `lineRunV` **必须在所有转角分支里赋值**。漏一次，转角后速度会跳回基准值冲出去。

### 段二必须禁用转角判据

段二（6.67~22.94 m）**全是圆弧，没有任何真直角**。但路上有两个十字
（L7×L8 @14.28 m、L8 @17.07 m），而**十字的灰度签名与直角完全相同**
（整条阵列压白）⇒ 横边命中必然误转 90°。

最要命的是 **14.28 m 那个**：过去之后仅 **490 mm** 就是 R292 的 90° 小弯，
在十字上误转 90° 后再也对不准入口。

```c
seg2NoCorner = (idx == 1);       // 段二
// 直接清 lineCorner / lineCornerArm / CntR / CntL
// ⇒ lineCorner 恒 false ⇒ 横边 / 观察窗 / 直角四条路径全部不可达
```

## 六、四圆区（R300 四连圆）

里程 22.944 ~ 26.760 m，R16 右 189° / R17 左 180° / R18 右 180° / R19 左 180°。

### 切点判据 = 分叉签名

灰度**和**陀螺都判不出切点（前视 66 mm 只差 7.3 mm，IMU 175° 只是兜底）。
真正可靠的是灰度阵列的**形状特征**：

> **中心 OUT4 仍亮 + 最外侧单独成簇**（簇数 = 2）⇒ 立刻换向，
> 方向由哪一侧张开给出。

手推 1418 帧验证：只 6 帧命中、**零误报**。

### 换向

只改 `c4Sign`，前馈钉 `±v/0.300 × 1.15`。
**第 3 次换向后还必须再走 45° 才算走完**（否则会少走 45° 就交回去）。

> ⚠️ 已知未解：**R18 那个右转角在提速版里过不去**。
> 已排除速度和权限（前馈几乎正好等于需求、权限还有 2 倍余量），
> 嫌疑在**切点 #2 翻号晚**：`C4_SEG_RAD = 3.05`（175°）只有 5° 余量，
> 而且切点没做 `C4_ARM_LEAD` 那样的滞后补偿 ⇒ R18 头一小段前馈还是左转。
> **降速治不了"方向错"，只能改判据。** 当前参赛版是 0.28 m/s，能过。

## 七、终点停车

赛道 `L12` 与 `L1` 是**同一条直线**（都是 y = 4800）⇒ **终点没有任何横线**
⇒ 灰度判不出"到头了"，只能按里程停。

```c
#define LINE_STOP_ODO_MM    36400.0f   // 停车判据里程（odo 读数）
#define LINE_STOP_BRAKE_MM    300.0f   // 提前减速距离
#define LINE_STOP_LAST_MM      25.0f   // 剩余小于此值 ⇒ 直接停
#define LINE_STOP_VMIN         0.06f   // 减速段末速
```

最后 300 mm 线性降速 → 剩 25 mm 时 `lineOn = false`、`forward/turn = 0`、
`PID_VEL.reset()`，同时置 `autoRunSt = 2`。

★ **两个必须注意的点**：

1. **停车块必须写在 `vCmd = forward + vTrim` 之后**。
   那一行每帧从 `robotMotion.forward` 重算 `vCmd`，写在前面等于没写。
2. **必须置 `autoRunSt = 2`**。车停在起点线上、灰度仍压着线，
   不锁的话下一帧就重新满足"就位"条件，自己又跑一圈。

**为什么是 36400 而不是 37020**：里程计有 **−2~−3.5% 负漂移**（23 m 处实测差约 0.5 m）。
`odo` 走到 36400 时，车的真实位置大约就是 37.0 m 的终点。
**停早了调大、停晚了调小，只改这一个数。**

## 八、板载记录仪（**参赛版没有，但这是最该补的一块**）

> ⚠️ **当前仓库里的固件没有内置记录仪**（`D` / `E` 命令不存在）。
> 完整实现是在后来那条提速线上做的，因为那条线没有通过整跑验证，
> 所以**记录仪代码没有随参赛版发布**。
>
> 但这恰恰是这个项目最值得先补的东西：**没有逐帧数据，调参就是掷骰子**。
> 设计要点、踩过的坑、以及"为什么必须在停稳后写 flash"，见
> [`docs/LOGGING.md`](../docs/LOGGING.md)。
>
> 下面描述的是它的设计目标，供你自己实现时参照。

3000 条 × 20 ms 环形缓冲存在 RAM，行程结束自动落盘 LittleFS（`/lg.csv`）。

| 命令 | 作用 |
|---|---|
| `D` | 导出（RAM 空时**自动改读 flash**） |
| `E` | 手动强制落盘（RAM 空时写一条测试记录自检） |

落盘触发条件：`lineOn` 下降沿 + 稳定 ≥1 s + `|vMeas| < 0.03` + ≥100 条。

★ **绝不能在跑动中写 flash**（会饿死控制环）。
★ `LittleFS.open(p, "w", true)` 第 3 个参数 `create` **必须显式 true**
（Arduino core 2.0.x 默认 false，会报 `no permits for creation`）。
首次挂载必报 `Corrupted dir pair` + `-84`，**属正常**（还没格式化）。

★ **如果你照抄我们的打印格式，有两个必然会踩的坑**：

1. `printf` 里写了 **13 个格式符但只传了 12 个参数** ⇒ 最后一列是**栈垃圾**，
   每次都变。**分析时只取前 12 列。**
2. 单位：`eD` 字段 = `lineEDot × 1000`（mm/s），`odo` 字段 = `mm / 100`
   ⇒ **换成米是 `字段 / 10`，不是 `/100`**。我们按 `/100` 用了两天，所有里程判断都是错的。

分析脚本见 `tools/`（**注意：解析 CSV 的那几个脚本需要你自己实现上面那个记录仪才能用**）：

| 脚本 | 用途 | 需要记录仪 |
|---|---|---|
| `_probe_alive.py` | 探活（发 `s` 看有没有回应）——**"没日志"不等于"固件挂了"** | ✗ |
| `_map_len.py` | 从 `.geom` 逐段累加算全程里程 | ✗ |
| `_watch_flat.py` | 实时看直道摆动幅值（靠状态帧，不靠记录仪） | ✗ |
| `_dump_lg.py` | 发 `D` 导出记录 | ✓ |
| `_an_dir2.py` | **陀螺航向积分**，判"到底转够没有"（最可靠的判据，别用均值） | ✓ |
| `_an_win.py` / `_an_l4.py` / `_an_c4.py` | 逐窗口 / L4 段 / 四圆区的逐帧分析 | ✓ |

## 九、串口命令（USB 921600，`\n` 结尾）

| 命令 | 作用 |
|---|---|
| `v<车速>` | 目标车体线速度 [m/s]（正 = 前进） |
| `t<偏航率>` | 目标偏航率 [rad/s]（正 = 左转，需先用 `g` 验证符号） |
| `w<L>,<R>` | 直接指定左右轮角速度 [rad/s]（绕过运动学，台架用） |
| `rw<轮半径>` / `lw<轮距>` | 默认 0.015045 / 0.144 |
| `kt<值>` | 偏航率环 P（默认 0.6） |
| `kv<P>,<I>` | 轮速外环 PI（默认 0.4, 0.8） |
| `yk<..>` / `yd<..>` / `yi<..>` | 巡线 Kp / Kd / Ki |
| `g` | 陀螺自检 3 s：手推车头向左，`GyroZ` 必须为正 |
| `c` | 重标陀螺零偏（阻塞 ~5 s，车必须静止放平） |
| `d0` / `d1` | 关 / 开 20 Hz 状态帧 |
| `s` | 急停 |
| `?` | 帮助 |

## 十、参数速查

| 参数 | 值 | 位置 |
|---|---|---|
| `Rw` / `Lw` | 0.015045 m / 0.144 m | `main.cpp` 顶部 |
| `lineKp` | 1.20 | 横向 mm → 角度 rad 的增益（乘在 `atan(e/LD)` 上） |
| 速度 | `autoRunV` 0.28 / `lineV2` 0.40 / `C4_V` 0.28 / `C4_EXIT_V` 0.25 | 见第四节 |
| `lineV2Odo` | 6700 mm | 提档里程门限 |
| `lineKpD` / `lineKdD` | 24 / 9 | 直接舵量 PD（按 `v` 归一化：`Kp = 24·v/0.28`、`Kd = 9·√(v/0.28)`） |
| `lineKboost` / `lineEboost` | 60 / 0.0068 m | 大偏差增速（`|e| > 6.8 mm` 后按斜率补舵） |
| `lineBoostMax` | 0.30 rad/s | 增速项的封顶，防过冲 |
| `lineTurnMax` | 2.00 rad/s | 舵量限幅 ⇒ 隐含最小可跑半径 `R_min = v/2.00` |
| `wheelMax` | 60 rad/s | 轮速限幅（0.9027 m/s） |
| `wDipMin` | 10.0 rad/s | 内轮最低速，切断打滑正反馈 |
| `holdKp/Kd/Ki` | 2.0 / 0.25 / 0 | 直道航向保持（Ki 默认关） |
| `turnKp` | 0.6 | 偏航率环 |
| `LINE_EDGE_MM` | 33.0 | 判定"线已到边缘"的 `|e|` 阈值（= 2 个灯距） |
| `LINE_STOP_ODO_MM` | 36400 | 终点停车（见第七节） |

> ★ **Kd 的上限是 12**。13 会在 6.7 mm 台阶上出尖峰，直接把环路打死。
> 这也是为什么"加大阻尼"这条路走不通——只能靠前馈把位置环的负担卸下来。
>
> ★ **`wheelMax = 60` 是一个隐形天花板**。它把 0.70 m/s 下的可执行舵量压到 0.87 rad/s，
> 而 10 mm 偏差就需要 1.02 ⇒ 位置环被钳成"恒速回正"⇒ 反而不摆。
> 一旦你为了提速把它抬到 68，这层隐形限幅就消失了，增益**第一次全额兑现**，就会摆。
> **抬 `wheelMax` 之后必须重新核算环路增益。**

## 编译

```bash
cd line-following
pio run -e esp32-s3-devkitc-1              # 编译
pio run -e esp32-s3-devkitc-1 -t upload    # 烧录
```

S3 上的 `Serial` 必须通过 `-DARDUINO_USB_CDC_ON_BOOT=1` 才能变成 HWCDC
（`platformio.ini` 已加好）。不加的话 UART0 没引到 USB 口，电脑一个字节都收不到。

> ⚠️ 连续跑完一趟之后**串口经常会掉**（COM 口消失），需要重插。
> 这是硬件限制，不是固件问题。
